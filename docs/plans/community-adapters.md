# 社区扩展整批适配

用户要求整批适配后集中修复。范围包含 AMD Cloud、DeepAI Code、DeepSeek Web、Gemini/AI Studio、Muse Web、压缩清理、历史召回、上下文折叠和搜索。

决定：保留两个扩展类型及固定 origin 沙箱；增强默认停用；凭据走 secrets；不复制现有 Kilo/通用兼容渠道；继续排除 WorkBuddy、CodeArts、华为云。

性能与规模：面向本机个人使用，遵循宿主的请求超时与有限 JSON 存储；不增加后台轮询或真实生成探测。

隐私：不自动读取浏览器或历史凭据，不把本机对话外发到未经用户配置的服务；召回范围需按项目/会话隔离。可靠性：增强失败保持原请求，渠道错误保留明确状态；不伪造可用性或无额度限制。

维护：按上游分别记录源码版本、许可与适配边界；新增宿主能力必须补齐接口和回归。已拉取 OFM 2.8.2 的真实扩展宿主，并进行临时数据目录验证，不能用目录占位代替完整适配。

实现决策：六个渠道、五个增强；保留沙箱限制，重型依赖由用户显式安装并单独启动的 localhost 社区桥运行。网页登录保留上游交互，不自动消费真实额度。搜索使用显式 [search] 请求增强；历史通过授权项目调用 deja CLI；可逆折叠提供按项目/会话归档和 CLI 取回。本批沿用 v1 渠道/增强契约，不伪装注册 search/unfold 工具，未迁移上游管理页面；2.8.2 的 v2 页面能力不在这批范围。

压缩采用原上游纯 pipeline，关闭遥测/采集入口及依赖全局检索存储的 CCR；折叠使用单独的可验证归档。真实 OFM 2.8.2 内核隔离集成检查已通过；真实账号生成与运行中 DSH Desktop UI 验收尚未执行。配置、凭据、测试依赖仅存在私有临时目录，不纳入仓库。
